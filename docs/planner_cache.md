# 캐시와 플래너 비교

W08은 계획 대기 시간을 줄일 수 있는지 확인하는 별도 실험입니다. 기존 기본값은
RRTConnect·캐시 사용 안 함입니다. 기존 `fixed_motion_v1`의 입력·평가 형식·과거 수치는 유지합니다.

## 선택과 검증

명령 서버의 내부 설정과 CLI에서 등록한 RRTConnect 또는 RRT를 선택할 수 있습니다.
캐시는 별도로 켜야 하며, 전체 관절의 coordinated 계획만 후보로 저장합니다.
Pose, 출발 시점 조정, 이미 승인한 계획의 실행과 이동이 필요 없는 요청은 캐시 대상이 아닙니다.
일반 명령의 기존 4필드 형식은 유지합니다.

캐시에는 검증을 통과한 새 경로를 저장합니다. 모델·환경·공구 없음·정책·플래너·구현 소스의
신원을 SHA로 묶고, 전체 관절 순서와 시작·목표를 확인합니다. 메모리 용량·개수·수명을 제한하며
재사용만으로 생성 시각이나 수명을 늘리지 않습니다.

기본 시작 자세 비교는 정확히 같은 값만 허용합니다. 실험에서는 최대 `0.0001 rad`의
시작 차이를 명시적으로 허용합니다. 이 경우 관측값을 바꾸지 않고 반환한 경로 사본의
첫 위치만 현재 관절 상태에 맞춥니다. 원본 경로와 원래 시작점은 유지합니다.
새 경로를 다시 저장하는 방식으로 시작점을 조금씩 이동시키지 않습니다.

재사용 후보도 다음 검사를 통과해야 합니다.

1. 현재 소스·native 거리 검사기·모델·정책·Planning Scene 신원 확인
2. 전체 관절·시작·끝점과 보간 위치 제한 확인
3. 첫 구간의 연속 위치·속도·가속도 검사
4. 기존 native 전체 경로 거리 검사와 MoveIt 상태 유효성 검사
5. 현재 상태·신원·취소·남은 계산 예산의 최종 확인

위치·경로·첫 구간 검사에서 후보를 거부하면 캐시에서 제거하고 같은 남은 예산으로 새로
계획합니다. 취소·예산 초과·전송 실패·신원 오류를 캐시 실패로 바꿔 재시도하지 않습니다.
캐시 적중은 실행 승인이 아닙니다. 계획마다 새 일회 검토를 발급하며 승인 뒤에는 검토한
동일 경로를 실행하고 IK·계획·캐시 조회를 다시 수행하지 않습니다.

소스·native·플래너 파일 검사는 캐시 조회부터 검토 발급까지 적용됩니다. 이미 발급한 계획의
승인 실행은 기존 모델·정책·Planning Scene·현재 상태·전체 경로 재검사 계약을 사용합니다.
이 범위를 모든 파일 변경에 대한 기존 승인 자동 폐기로 확대해 설명하지 않습니다.

첫 구간 검사는 JTC의 linear/cubic/quintic 보간을 사용합니다. 재앵커한 첫 위치가 작게 달라도
짧은 구간의 속도·가속도가 커질 수 있으므로 끝점이나 위치 표본만으로 통과시키지 않습니다.
현재 생성하는 MoveIt 가속도 한계는 `1.0 rad/s²`입니다. 이는 설정 한계이며 실제 추종 가속도나
플래너의 축소 비율 달성을 측정한 수치가 아닙니다. 나머지 구간의 동역학·실물 성능까지 증명하지 않습니다.

## 실제 실험

두 플래너를 등록한 현재 모델을 생성한 뒤 새 출력 디렉터리와 빈 ROS 도메인을 사용합니다.
원본 런타임을 공유하는 작업 환경에서는 전체 런타임 빌드 대신 해당 환경의 격리 모델 생성 절차를 따릅니다.

```bash
PYTHONPATH=src .venv/bin/python prepare_workcell.py --workcell fr5_ur5e
source ./manipulation_env.sh
python3 benchmark_planner_cache.py --list
python3 benchmark_planner_cache.py --mode functional --domain 229 \
  --output runtime/validation/planner-cache-functional-new
python3 benchmark_planner_cache.py --mode performance --repeats 3 --domain 228 \
  --output runtime/validation/planner-cache-performance-new
```

`manipulation_env.sh`를 읽은 뒤 `PYTHONPATH=src`로 덮어쓰지 않습니다. 이 환경은 ROS Python
패키지 경로도 포함합니다. 실제 실행은 모든 행·입력·모델·구현 소스 사본과 SHA를 먼저 보존하고,
실행 중 해당 입력이 달라지면 중단합니다. 중단 뒤 자동 재시도하거나 같은 출력에 덮어쓰지 않습니다.

| 비교 | 고정한 조건 | 바꾸는 조건 |
| --- | --- | --- |
| 플래너 | 캐시 사용 안 함, 같은 입력·후보 1개·계산 예산 | RRTConnect / RRT |
| 캐시 | RRTConnect, 같은 입력·후보 1개·계산 예산 | 사용 안 함 / cold / warm |

기본 성능 표본은 각 조건 3회, 총 12개입니다. warm의 선행 채움 3개는 별도 준비 행입니다.
기능 검사와 시험용 오류 주입도 성능 표본에서 제외합니다. 실제 시작 자세는 일반 명령과
피드백으로 맞추고, 보정 비용·관측 오차를 별도로 남깁니다.

캐시 조회 적중, 재검증을 통과한 실제 재사용, 검증 거부 뒤 새 계획 복귀는 서로 다른 결과입니다.
요청 수신부터 새 검토 준비까지의 시간을 같은 종점으로 비교합니다. 실험의 계산 예산도 모든
조건에서 마지막 검토 신원 확인까지 포함합니다. 기존 캐시 미사용 명령 서버의 기본 처리 순서는 유지합니다.
조회·신원 확인·전체 재검증·복귀 비용과 계획 RPC 시간을 따로 기록합니다.
사람의 승인 대기와 준비 동작 시간은 계산 성능 표본에 넣지 않습니다.
계산 예산 5초는 협력적 검사와 RPC의 남은 허용 시간이며 프로세스를 5초에 강제 종료한다는 뜻이 아닙니다.

실패와 미실행을 보존하고 작은 표본은 개별값·중앙값·최댓값을 제시합니다.
모든 조건에 유효한 측정 표본이 20개 이상일 때만 p95를 표시합니다.
GetMotionPlan 응답에는 실제 선택한 플래너 ID가 없으므로 요청값, 조회한 등록 설정,
실제 MoveIt 로그를 각각 근거로 남깁니다.

실험 결과는 이 고정 입력에서의 계획 비교입니다. 전체 요청→동작 지연, 다른 작업의 성능,
최단 경로와 장시간 신뢰성을 보장하는 수치로 확대하지 않습니다.
