# HTML 리포트 작성 기준 v1.9

v1.9 「뷰어 개발 방향성」의 정보 구조와 표시 규칙을 재사용합니다.
대상은 개발 사례·기술 설계·대안 검토 등 사람이 작성하는 HTML 리포트입니다.
[HTML 템플릿](templates/engineering-report-v1.9.html)을 새 리포트 폴더의 `index.html`로 복사하고 대괄호 항목을 채웁니다.
[기준 구현: 뷰어 개발 방향성](../operator/viewer-direction-2026-10-22/index.html)의 문서 내용과 기준 코드·수치를 새 리포트에 그대로 재사용하지 않습니다.

## 1. 콘텐츠 구조

- 도입부: 제목, 소개 두 줄, 대상·기준 코드·확인일·문서 버전을 제시합니다.
- 개발 요약: 개발 방향·구현 상태·도입 배경·구현 방식을 구분합니다.
- 본문: 현재 구성 → 선택 근거 → 검증 결과·한계 → 대안 비교 → 개선 계획 → 비교 검증 설계 순서를 기본으로 합니다.
- 마무리: 검토 범위·미검증 사항과 근거 목록을 제공합니다.
- 적용하지 않는 절은 생략할 수 있으며, 설명의 목적에 맞게 순서를 조정합니다.
- 특정 로봇·작업 환경은 검증 사례로 표기하고, 지향하는 범용 기능의 구현 완료를 암시하지 않습니다.

## 2. 목록·표 선택

- 역할·기준·후보 식별자처럼 항목명과 설명의 대응이 필요할 때만 `<dl><div><dt>…</dt><dd>…</dd></div></dl>`로 구성합니다.
- 순서 없는 병렬 항목과 관찰 가능한 완료 조건은 `ul`을 사용합니다.
- 실행 순서·단계·우선순위를 전달해야 할 때만 `ol`을 사용합니다.
- 여러 대상의 같은 속성을 비교할 때는 표를 사용하고 열 제목과 행 제목을 지정합니다.
- 긴 설명을 한 항목에 묶지 않고, 사실·조건·판정 단위로 분리합니다.
- 완료 조건은 ‘확인·표시·정의·확보’처럼 검증 가능한 항목으로 기술합니다.
- 좌우 카드에는 같은 목록 구조·레이블 폭·구분선·여백을 적용합니다. 내용만으로 불필요한 행을 늘리지 않습니다.

## 3. 제목과 시각 자료

- 절 제목은 핵심 주제를, 소제목은 해당 구성의 역할을 드러냅니다.
- 그림·표·도식 제목은 `그림 1. 핵심 대상`, `표 1. 핵심 대상`, `도식 1. 핵심 대상`으로 통일합니다.
- 번호는 유형별 문서 등장 순서로 부여하고, 각 제목에 고유 ID를 지정합니다.
- 제목에는 긴 설명을 넣지 않습니다. 조건·미측정·해석 한계는 바로 아래 주석에 유지합니다.
- 그림 설명은 짧은 제목과 원본 링크를 기본으로 하고, 의미 있는 대체 텍스트를 제공합니다.
- 제안 구조는 ‘확장안’, 미실시 시험은 ‘평가 계획’처럼 제목에서도 상태가 드러나게 합니다.
- 표에는 `caption`, 열·행 머리글을 사용하고 관련 주석을 `aria-describedby`로 연결합니다.

## 4. 문체·용어·단위

- 제3자 개발자에게 구현 내용과 판단 근거를 소개하는 문장으로 작성합니다.
- 설명 본문은 ‘합니다’체, 제목·짧은 요약·완료 조건은 명사형으로 통일합니다.
- 구현 이력은 과거형, 현재 지원은 현재형, 후속 작업은 계획·조건형으로 구분합니다.
- 설명문은 마침표를 사용하고, 명사형 제목·짧은 항목은 마침표를 생략합니다.
- 같은 구성요소에는 같은 명칭을 사용하며 표시부·상태 렌더러·물리 계산 등의 경계를 유지합니다.
- Scene은 문맥에 맞게 씁니다. 로봇·설비의 구성과 배치는 ‘작업 환경’, 공유 물리 계산은 ‘물리 시뮬레이션’, 뷰어의 표시는 ‘3D 화면’ 또는 ‘3D 표시’로 설명합니다. 그래픽 객체·파일 구조와 API 이름은 `Scene`·`Planning Scene` 등 원래 용어를 유지합니다.
- 숫자와 단위는 `30 mm`, `250 ms`, `4 Hz`, `5 fps`처럼 띄어 씁니다. 제품명·코드 식별자는 원형을 보존합니다.
- 화면 크기는 `960 × 640`, 관절 단위는 `rad`·`deg` 등으로 명시합니다.

## 5. 사실·제안·측정 구분

- 현재 구현, 기존 검증, 설계 분석, 확장안, 미측정·미검증 범위를 문맥과 레이블로 구분합니다.
- 설정 상한·조회 예약 간격·영상 인코딩 속도를 실제 표시 성능으로 표기하지 않습니다.
- 측정 결과에는 코드·환경·입력·표본·반복 조건과 해석 범위를 함께 제시합니다.
- 일부 고정 회귀 검증을 장시간 안정성·전체 공간 성공률·실물 성능으로 확대 해석하지 않습니다.
- 미실시 비교에는 성능 순위를 부여하지 않으며, 판정은 후속 검증 결과에 따라 갱신합니다.

## 6. 반응형·인쇄·근거 패키징

- 한국어는 단어 단위 줄바꿈을 유지하고, 코드·긴 URL은 안전하게 감싸 가로 넘침을 방지합니다.
- 좁은 화면에서는 좌우 카드와 정의 목록을 세로로 전환하고, 긴 표는 접근 가능한 가로 스크롤로 제공합니다.
- 인쇄 시 고정 내비게이션·조작 버튼을 숨기고 표·본문·출처를 읽을 수 있는 폭과 크기로 조정합니다.
- 최소한 좁은 모바일·태블릿·데스크톱에서 넘침, 이미지 누락, 앵커·키보드 조작을 확인하고 인쇄 배치를 검토합니다.
- HTML·이미지·근거 데이터·검토 기록을 같은 배포 패키지에 보존하고 상대 경로를 검증합니다.
- 저장소 근거는 기준 커밋 링크로 고정하고 외부 문서는 확인일을 기록합니다.
- 파일 해시는 게시 형식에 맞춰 갱신하며, 게시 목록 등록과 실제 산출물 포함 여부를 별도로 확인합니다.

## 7. 기존 리포트와의 호환성

- 이 기준안은 기존 성능 리포트의 `report.json` 스키마를 자동 변경하지 않습니다.
- 기존 공통 생성기의 자동 생성 출력과 검증 스냅샷을 수작업으로 교체하지 않습니다.
- 데이터 형식·생성기·게시 목록 변경은 별도 범위로 검토하고 기존 검증을 통과해야 합니다.
