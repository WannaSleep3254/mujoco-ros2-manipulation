# 고정 베이스와 다중 로봇 작업장면 구현 계획

[프로젝트 README](../../README.md) · [모델별 자료](../robots/README.md) · [검증 안내](../verification.md)

작성일: **2026-10-08** · 상태: **계획 작성, 기능 구현 전**

기준 코드는 [`b4ebef2`](https://github.com/WannaSleep3254/mujoco-ros2-manipulation/tree/b4ebef2)입니다.
이 문서는 원하는 형태의 고정 받침대를 추가하고, 같은 작업장에서 FR5와 UR5e를 제어하기 위한 작업 순서·변경 대상·완료 기준을 정의합니다.
아래 새 파일명, 설정 형식, 실행 명령은 구현 제안입니다. 현재 사용할 수 있는 기능과 구분합니다.

## 목표와 범위

**고정 베이스 + FR5 → FR5·UR5e 공동 배치 → 팔별 궤적 제어 → 공동 충돌 회피 → 성능 측정** 순서로 진행합니다.
기존 FR5·FR10·UR5e 단일 로봇 실행과 모델별 문서·검증 기록을 유지합니다.

| 구분 | 이번 구현 목표 | 이후 확장 |
|---|---|---|
| 베이스 | 고정 사각·원통 받침대, 위치·방향 설정, CAD 메시 입력 경로 | 리니어 레일·회전대·이동 플랫폼 |
| 로봇 배치 | FR5 한 대, FR5 + UR5e 두 대, 같은 모델 두 대의 이름 중복 검사 | FR10 교체와 세 대 배치 |
| 제어 | 위치 서보, 팔별 JointTrajectoryController, 전체 상태 공유 | 그리퍼·도구 TCP, 물체 전달 |
| 계획 | 팔별 계획, 순서 조정, 양팔 관절 공간 공동 계획 | 접촉 조립·힘/순응 제어 |
| 검증 | 좌표계 일치, 충돌 장면 일치, 완료 피드백, 정상 종료, 성능 기록 | 실제 로봇 연결 |

실제 베이스 도면이 없는 동안에는 기본 도형으로 진행합니다. CAD 적용은 파일·치수·단위가 확보된 뒤 추가하며, 두 대 제어의 선행 조건으로 두지 않습니다.
FR10은 먼저 기존 프로필의 재사용·교체를 검증하고, 세 대 동시 실행은 두 대의 성능 측정 후 결정합니다.

현재 MuJoCo 바닥은 MoveIt 계획 장면에 등록하지 않았습니다. 여러 로봇을 배치한 장면, 공동 계획 그룹, 로봇 간 충돌 검사도 아직 구현하지 않았습니다.

## 설정과 생성 구조

### 모델과 작업장면 분리

`config/robots/*.yaml`은 제조사 모델의 출처·관절 순서·한계·게인·기본 자세를 계속 관리합니다.
새 `config/scenes/*.yaml`은 받침대·작업대·장애물과 로봇별 설치 위치·방향을 관리합니다.
`left`, `right`는 배치 인스턴스이고, `fr5`, `ur5e`는 모델입니다. 같은 모델도 서로 다른 인스턴스로 두 번 배치할 수 있어야 합니다.

```text
모델 프로필 FR5 / UR5e + 작업장면 설정
                 |
             장면 생성기
                 |
       +---------+------------------+
       |                            |
  합성 URDF + SRDF             합성 MJCF
       |                            |
  MoveIt / TF             MuJoCo 물리 장면 하나
       |                            |
       +-- 제어기 설정·관절 이름 ----+
```

생성물은 `runtime/generated/scenes/<scene_id>/`에 모읍니다.
URDF·MJCF·제어기 YAML·MoveIt YAML·출처 JSON을 같은 장면 설정에서 생성하고, 기존 단일 모델 생성물과 분리합니다.
출처 JSON에는 장면 설정, 각 모델 프로필, 제조사 커밋, 사용 메시의 해시와 인스턴스별 관절 대응표를 기록합니다.
어느 입력이든 바뀌면 기존 생성물을 재생성하도록 검사합니다. 생성 XML을 직접 수정하는 방식은 사용하지 않습니다.

### 장면 YAML 초안

다음은 **아직 지원하지 않는 설정 형식의 예시**입니다. 치수·간격은 설명용 초안이며, 로봇의 도달 범위·초기 자세·충돌 검사 후 조정합니다.
받침대의 크기는 전체 길이이고 위치는 중심입니다. 로봇 설치 위치는 받침대 중심 좌표계에 대한 상대 위치입니다.

```yaml
schema_version: 1
id: fr5_ur5e_cell
physics:
  timestep_s: 0.002
  integrator: implicitfast
supports:
  - id: left_pedestal
    shape: box
    size_xyz_m: [0.4, 0.4, 0.6]
    xyz_m: [-0.75, 0.0, 0.3]
    rpy_rad: [0.0, 0.0, 0.0]
  - id: right_pedestal
    shape: box
    size_xyz_m: [0.4, 0.4, 0.6]
    xyz_m: [0.75, 0.0, 0.3]
    rpy_rad: [0.0, 0.0, 0.0]
robots:
  - instance: left
    model: fr5
    prefix: left_
    mount:
      parent: left_pedestal
      xyz_m: [0.0, 0.0, 0.3]
      rpy_rad: [0.0, 0.0, 0.0]
  - instance: right
    model: ur5e
    prefix: right_
    mount:
      parent: right_pedestal
      xyz_m: [0.0, 0.0, 0.3]
      rpy_rad: [0.0, 0.0, 3.141592653589793]
```

위 예시에서 두 로봇의 설치 높이는 world 기준 z = 0.6 m입니다.
길이는 m, 각도는 rad로 통일하고, RPY는 `Rz(yaw) Ry(pitch) Rx(roll)`로 변환합니다.
MJCF의 box 반치수·쿼터니언과 URDF의 치수·자세로 각각 변환합니다.
입력 검사에서는 중복 ID·prefix, 미등록 모델, 순환하는 부모 관계, 0 이하 치수, 잘못된 자세를 거부합니다.

### 베이스와 환경의 처리

고정 연결은 `world → pedestal → <prefix>base_link`로 구성합니다.
MuJoCo에서 관절이 없는 자식 body는 부모에 고정되므로, 고정 베이스에 구동 관절을 추가하지 않습니다.
같은 고정 구조를 URDF에도 반영합니다. [MuJoCo body·joint 정의](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-joint)

로봇에 연결된 베이스는 URDF의 고정 링크·충돌 형상으로 표현하고, 주변 작업대·장애물은 같은 설정에서 MoveIt CollisionObject를 등록합니다.
MoveIt의 적용 서비스로 등록 결과를 확인한 뒤 계획을 받습니다. [MoveIt Humble Planning Scene API](https://moveit.picknik.ai/humble/doc/examples/planning_scene_ros_api/planning_scene_ros_api_tutorial.html)

첫 공통 바닥은 유한한 두께의 box로 만들고, 양쪽에서 작업 범위·상면 높이를 일치시킵니다.
같은 물체를 URDF 링크와 CollisionObject에 이중 등록하지 않습니다. 고정 접합부의 충돌 제외는 대상 쌍을 한정하고, 팔과 받침대 사이의 충돌은 제외하지 않습니다.

CAD는 시각용과 충돌용 형상을 분리하고, 원본 파일·이용 조건·단위·축척·원점을 기록합니다.
일반적인 MuJoCo 메시 충돌의 convex hull 근사를 고려해, 구멍·오목한 공간이 필요한 형상은 여러 볼록 형상으로 나눕니다.
같은 충돌용 형상을 MoveIt에도 전달합니다. [MuJoCo mesh 정의](https://mujoco.readthedocs.io/en/stable/XMLreference.html#asset-mesh)

## 다중 로봇 제어 구조

초기안은 **합성 MJCF 하나, SystemInterface 하나, controller_manager 하나, 상태 발행 하나, 팔별 궤적 제어기 두 개**입니다.
여러 하드웨어 플러그인을 별도로 실행하면 같은 물리 세계가 공유된다고 가정하지 않습니다.
현재 고정된 `mujoco_ros2_control` 0.1.2에서 12관절을 처리할 수 있는지는 M0의 시험 구현으로 확인합니다.

```text
MoveIt: left_arm / right_arm / both_arms
                    |
       controller_manager 하나
          |                    |
   left_controller       right_controller
          |                    |
          +------ SystemInterface 하나
                             |
             MuJoCo: FR5 + UR5e + 베이스·환경
                             |
                  /joint_states와 /clock
```

| 항목 | 구현 방침 |
|---|---|
| 이름 | `left_j1`, `right_shoulder_pan_joint` 등 관절·링크·구동기를 prefix로 구분 |
| 참조 | 메시·재질·접촉 제외·SRDF·초기 자세도 이름 대응표로 변환하고, 미해결 참조를 검사 |
| 좌표계 | 공통 world는 하나. 각 모델의 기존 world 연결을 정리해 TF의 이중 부모 방지 |
| 시간 | 공통 `/clock`의 발행 노드 하나. 각 노드에 `use_sim_time` 적용 |
| 상태 | JointStateBroadcaster에서 전체 12관절을 발행하고 robot_state_publisher 하나로 전달 |
| 제어기 | 좌우 6관절씩 담당. 다른 팔의 관절을 지령하지 않도록 Action 연결 생성 |
| 계획 | move_group 하나에 전체 로봇·환경 유지. 팔별 그룹과 공동 그룹 정의 |
| 끝단 | FR5는 `left_wrist3_link`, UR5e는 `right_tool0`. 독자적인 도구 TCP는 후속 작업 |

ROS namespace만으로 모델 내부의 TF 프레임 이름이 바뀌지는 않습니다. 이름 변환은 합성 모델에 적용합니다.
팔별 그룹과 이름 분리는 [MoveIt 공식 다중팔 예제](https://moveit.picknik.ai/main/doc/examples/dual_arms/dual_arms_tutorial.html)를 참고합니다.
해당 예제는 Rolling 대상이므로, 현재 Humble에서 사용할 설정·API는 별도로 확인합니다.

## 단계별 작업과 완료 기준

체크 항목은 **모두 구현 대기**입니다. 기간을 고정하지 않고, 각 단계의 검증을 통과한 뒤 다음으로 진행합니다.

### M0: 기존 기준 저장과 공유 시뮬레이션 시험

- [ ] 현재 FR5·FR10·UR5e의 생성·ROS·종료 검증을 다시 실행하고 비교 기준 JSON을 저장한다.
- [ ] 최소 두 팔 모델에서 플러그인 하나로 12관절을 읽고 쓰며, 두 궤적 제어기를 활성화한다.
- [ ] `/clock` 발행 노드 하나, 전체 관절 상태, 좌우 Action과 명령 대상을 확인한다.
- [ ] 제약이 있으면 플러그인 수정 범위·고정 버전·기존 종료 패치와의 호환성을 기록한다.

**완료 기준:** 좌우 관절이 별도로 움직이고, 한쪽 명령이 다른 팔의 목표를 바꾸지 않으며, 전체 프로세스가 정상 종료한다.
시험 성공을 공동 계획 대응 완료로 간주하지 않는다.

### M1: 장면 설정과 FR5 고정 베이스

- [ ] 장면 스키마·입력 검사·출력 해시를 구현하고 `fr5_pedestal`을 준비한다.
- [ ] box·cylinder부터 지원하고, 위치·방향을 설정으로 변경할 수 있게 한다.
- [ ] 합성 URDF/MJCF에 설치 변환을 반영하고, 바닥·장애물을 MoveIt에 등록한다.
- [ ] 원점 외 위치와 yaw 회전에서 MuJoCo·URDF 순기구학의 설치 프레임과 끝단 자세를 비교한다.

**완료 기준:** 3자세에서 위치 오차 1e-6 m 이하·회전각 오차 1e-6 rad 이하. MuJoCo/RViz의 받침대·로봇·장애물이 일치한다.
알려진 충돌 목표를 MoveIt이 거부하고, 실행 가능한 우회 경로를 실행한다. 기존 단일 모델 검증도 유지한다.

### M2: 임의 형상과 모델 재사용

- [ ] 베이스 STL/OBJ 입력, 축척·설치 원점, 별도 충돌용 형상을 설정할 수 있게 한다.
- [ ] 구멍·오목한 형상은 여러 볼록 부품으로 구성하고 양쪽 엔진의 형상·배치를 확인한다.
- [ ] 같은 단일 로봇 장면에서 FR5를 FR10으로 교체하고 베이스·설치 정보를 재사용한다.

**완료 기준:** 메시 변경 시 재생성이 요구되며, 의도한 빈 공간은 통과하고 막힌 공간은 통과할 수 없음을 확인한다.
CAD 미제공 시 기본 형상·모델 교체까지 완료하고, CAD 적용은 미완료로 남긴다. M3는 진행할 수 있다.

### M3: FR5·UR5e 공동 장면 합성

- [ ] `fr5_ur5e_cell`을 추가하고, 모든 참조의 prefix 처리와 초기 자세의 이름 대응을 구현한다.
- [ ] 공통 물리 설정·공유 제어·단일 시계를 정식 장면 Launch에 연결한다.
- [ ] FR5 두 대를 배치하는 검사도 준비해, 다른 모델 조합에서 드러나지 않는 이름 충돌을 검사한다.
- [ ] 베이스 지지면, 초기 자기·상호 충돌, 시각 형상과 충돌 형상을 확인한다.

**완료 기준:** 이름·TF·제어기 담당 관절에 중복이 없고, 12관절 모두를 명령·관측할 수 있다.
양팔의 단일·연속 목표가 수렴하며, 필요한 고정 접합 외에는 의도하지 않은 접촉이 없다.

### M4: 팔별 MoveIt 계획과 실행 관리

- [ ] `left_arm`·`right_arm`의 SRDF, 팔별 IK, 관절 제한, 제어기 대응을 생성한다.
- [ ] 정지한 팔도 전체 Planning Scene에 포함해, 한쪽 계획 시 충돌을 검사한다.
- [ ] Action 결과와 상태 수렴을 결합하는 기존 완료 판정을 각 인스턴스에 적용한다.
- [ ] 장면 등록 전 요청, 미등록 관절, 한계 밖 목표, 계획 실패를 실행으로 넘기지 않는다.

**완료 기준:** Action 성공과 모든 대상 관절의 오차 0.01 rad 미만을 새 상태 메시지 10회 연속으로 확인한다.
다른 팔·장애물을 고려한 경로가 실행되며, 충돌 목표 거부 시에는 지령이 전송되지 않는다.
별도로 계획한 두 경로의 성공만으로 동시 실행을 허용하지 않는다.

### M5: 공동 충돌 회피와 시간축을 맞춘 실행

- [ ] 먼저 팔별 순차 실행을 구현하고, 이동 후 전체 상태를 다음 계획에 반영한다.
- [ ] `both_arms` 12관절 그룹을 추가해 전체를 하나의 관절 공간에서 계획한다.
- [ ] 끝단 Pose가 필요하면 팔별 IK로 후보를 구하고 전체 관절 목표로 검사·계획한다.
- [ ] 공통 궤적을 두 제어기에 배분하고, 시작 시각·제어기 준비 상태·실제 시작 차이를 검증한다.
- [ ] 한쪽 거부·취소·이상·시계 정지 시 다른 팔도 정지·위치 유지하는 처리를 검증한다.
- [ ] 양팔 동작 시간을 겹친 상태열에서 상호 충돌을 검사하고, MuJoCo 물리 스텝에서 의도하지 않은 접촉을 기록한다.

**완료 기준:** 개별 계획의 동시 실행에서는 간섭하는 예제에서, 순서 조정 또는 공동 계획으로 회피한다.
두 Action과 양팔 수렴이 모두 확인된 시점만 전체 완료로 판정한다. 실패 주입 시 다른 팔이 계속 움직이지 않는다.
시작 차이 허용값은 M0의 측정으로 정하고, 결과 JSON에 허용값·실측값을 남긴다.
이산 충돌 검사는 검사 간격·한계를 명시하며, 연속 시간의 무충돌 보장으로 해석하지 않는다.

### M6: 성능 평가와 공개 자료

- [ ] 1대·2대, headless·GUI별로 같은 환경·정의된 목표·난수 조건을 사용하는 측정 절차를 준비한다.
- [ ] 준비 5초 후 60초간 실시간 배율을 측정하고, 계획은 20회의 성공률·시간 중앙값·95백분위수를 기록한다.
- [ ] `/clock`과 실제 경과 시간으로 실시간 배율을 계산하고, 관절 상태의 실제 수신 주기·CPU·RAM·GPU 사용량을 기록한다.
- [ ] 제어 주기 지연은 별도 계측을 추가해 기록하고, 상태 수신 주기와 구분한다.
- [ ] GUI 닫기·SIGINT·Action 취소 후 자식 프로세스 잔류·크래시·종료 코드를 확인한다.
- [ ] 기존 3모델 회귀 결과, 장면도, MuJoCo/RViz 스크린샷, 짧은 영상, 출처를 정리한다.

**완료 기준:** 실행 조건·실패 사례를 포함한 재현 가능한 결과를 공개한다. GTX 1050 Ti의 2대·3대 성능은 사전 확정하지 않는다.
같은 목표의 도달 가능성이 모델마다 다르면 조건을 설명하고 비교한다.
3대 확장은 2대의 실시간 배율·계획 시간·자원 사용량 확인 후 착수한다.

## 변경 예정 파일과 산출물

아래 새 파일들은 아직 존재하지 않습니다. 첫 구현에서 역할을 확정하고, 필요하면 통합합니다.

| 변경·추가 대상 | 역할 |
|---|---|
| `config/scenes/*.yaml` | 베이스, 환경, 인스턴스, 설치 변환, 공통 물리 조건 |
| `scene_config.py` | 장면 입력 검사, 이름 대응, 좌표 변환, 생성물 정합성 검사 |
| `prepare_scene.py` / `prepare_robot.py` | 모델 변환 공통화, 합성 URDF/MJCF, 초기 자세, 출처 생성 |
| `workcell.launch.py` / `run_scene.sh` | 물리 장면 하나·여러 제어기·MoveIt 실행과 공통 종료 처리 |
| `packages/workcell_moveit_config/` | 합성 로봇의 그룹·IK·제어기 대응·RViz 설정 |
| `publish_scene.py` | 설정에서 환경을 등록하고 적용 완료 확인 |
| `verify_scene.py` / `tests/` | 좌표·이름·수렴·상호 충돌·실패 처리·종료 검증 |
| `runtime/generated/scenes/<id>/` | 자동 생성 URDF/MJCF/YAML/출처. Git 제외 |
| `docs/scenes/<id>/` | 확정 설정·실행 방법·검증 JSON·이미지·영상 링크 |

기존 `run_sim.sh robot:=fr5` 등의 명령은 계속 단일 로봇용으로 사용합니다.
새 장면 CLI는 구현 후 다음 형태로 제공할 예정입니다. **현재 실행할 수 있는 명령이 아닙니다.**

```bash
# 향후 CLI 제안: 해당 파일과 옵션은 미구현
.venv/bin/python prepare_scene.py --scene fr5_pedestal
bash run_scene.sh scene:=fr5_pedestal
bash run_scene.sh scene:=fr5_ur5e_cell
source ./manipulation_env.sh
python3 verify_scene.py --scene fr5_ur5e_cell --domain 93
```

생성기·제어·Launch를 변경한 단계에는 기존 단일 모델 검증도 수행합니다.

검증 결과 링크가 확보된 항목만 완료로 변경합니다.
이번 공개는 이 계획서와 README 안내 갱신이며, 기능 구현 완료 항목은 추가하지 않습니다.

## 설계 중 확정할 입력
