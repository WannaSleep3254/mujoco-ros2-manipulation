Project overview

빈피킹 중심의 작업 계획과 양팔 경로 개선

MoveIt 2 기반을 유지하고, 지연 원인·파지 후보·실행 계약을 단계별로 개선합니다.

개발 방향
이기종 복수 로봇의 작업을 공통 요청·검사·실행 흐름으로 연결합니다. 빈피킹을 우선하고 팔레타이징·조립으로 확장합니다.
구현 상태
현재 사례는 FR5·UR5e 양팔 12관절입니다. 공동 관절 계획·출발 조정·최종 검사·취소·요청 기록을 지원합니다. 파지 후보 생성과 물체 작업은 후속 범위입니다.
우선 과제
약 2초로 관측한 지연의 구간을 식별하고, 30 mm 간격 조건의 홈 복귀 거부를 재현합니다. 유효한 시작·목표에는 제한된 공간 재탐색을 연결합니다.
선정 기준
간격·충돌 조건을 만족하는 후보 사이에서 우회 길이·계산 비용·전체 완료 시간을 비교합니다. 플래너 교체와 실물 적용은 같은 입력·실행 계약의 비교 결과로 판단합니다.

약 2초 지연과 후보 선정의 의미

초기 질의의 약 2초는 지령 후 계산·후보 선정에 대한 관측입니다. 현재 자료의 오프라인 출발 탐색 시간이나 수신→최초 이동 시간과 같은 측정으로 확정할 수 없습니다. 먼저 같은 요청의 시간 구간과 후보 종류를 연결합니다.

현재 후보
출발 조정은 어느 팔을 얼마나 늦출지 비교합니다. 전용 간섭 검증은 공동 관절 경로를 비교합니다. 두 후보 모두 물체의 파지 자세·IK 후보와 다릅니다.
현재 설정
상시 요청은 명시적 RRTConnect를 요청하며 MoveIt 내부 시도 수는 3회입니다. 개별 계획 허용 시간은 기본 5초와 잔여 요청 예산의 제한을 받습니다. 이미 구현된 설정을 단순히 RRTConnect로 바꾸는 것이 새 개선안은 아닙니다.
계측 기반
요청 구간·계획 서비스 왕복·응답 planning_time·출발 탐색·거리 계산 기록이 있습니다. 부족한 구간을 보강하고 실제 문제가 발생한 입력에서 다시 연결해 측정합니다.
시간 해석
서비스 왕복에서 planning_time을 뺀 차이를 ROS 통신 시간으로 단정하지 않습니다. 대기·요청 처리·후처리도 포함될 수 있으며 서버 내부 계측이 필요합니다.

기존 계측의 적용 범위: 명령 규약 · 계획 요청 · 요청 회귀 기록

지연 개선 원칙: RRTstar 또는 ROS가 원인이라는 가정, 계획 예산 0.1초로 수십 ms 응답을 보장한다는 가정은 채택하지 않습니다. 설정·시도 수·충돌 검사·후처리·예약 대기를 분리해 비교합니다.

거부 원인과 재계획의 경계

  • 시작·목표 상태: 실제 시작 자세나 반환된 끝점이 거리 조건을 어기면 중간 경로의 우회만으로 해결할 수 없습니다. 목표 허용오차·현재 추종 자세와 함께 원인을 보존해야 합니다.
  • 중간 경로: 시작·목표는 유효하지만 도중에 간격이 부족한 경우에는 다른 공간 경로나 실행 시점을 검토할 수 있습니다.
  • 예산·취소: 기본 계산 예산은 30 s(wall)이며 명령 서버의 시작 옵션으로 조정합니다. 현재 중단 확인은 협력식입니다. 후보 수만 제한한 재시도 루프를 붙이면 취소·예산 동작이 달라질 수 있습니다.

우선 과제: 30 mm 조건의 홈 복귀 거부를 고정 입력으로 재현하고 시작·끝점·중간 경로의 어느 조건에서 실패했는지 구분합니다. 조건을 임의 완화하기보다 실패 유형에 맞는 목표 수정·후보 선택·재계획을 설계합니다. [개발 우선순위]

02 / Alternatives & decisions

계획 계층과 기술 선택

MoveIt 2를 유지한 개선을 기준선으로 두고, 전역 경로 탐색·궤적 최적화·피드백 제어의 역할을 나눠 대안을 비교합니다. 아래 선정 판단은 설계 제안이며 프로젝트에서 새 대안의 성능을 측정하지 않았습니다.

전역 탐색·궤적 개선·제어의 구분

표 3. 계획 방식의 역할
방식해결하는 문제비교 시 확인
샘플링 기반 탐색관절 공간의 연결 가능한 경로를 찾습니다. OMPL/RRTConnect가 현재 기반입니다.유한 시간 내 성공·최단 경로를 보장하지 않습니다. 작업 환경·검사 해상도·예산에 따라 성공과 비용이 달라집니다.
궤적 최적화초기 궤적을 길이·매끄러움·거리 등 비용과 제약에 맞게 개선합니다. TrajOpt가 비교 후보입니다.초기 경로와 문제 구성에 영향을 받습니다. 동역학·토크 제한은 모델과 제약에 넣어야 반영됩니다.
MPC·반복 최적제어관측 상태에서 유한 구간의 제어 문제를 반복해서 풉니다. MJPC 등은 이 계층에서 검토합니다.샘플링·미분 기반 방법 모두 사용할 수 있습니다. 제어 입력·관측 지연·모델 오차·실행 주기를 함께 평가합니다.

샘플링도 수학적 알고리즘입니다. “샘플링 대 수학”으로 양분하기보다 전역 탐색 → 궤적 개선 → 피드백 제어의 결합을 검토합니다. MoveIt OMPL · Tesseract/TrajOpt · MJPC

현재 요청 경로의 개선 대안

표 5. 개선 대안과 적용 조건
방향적용 목적통합·검증 항목선택 조건
A. 출발 조정 유지
현재 기반		유효한 팔별 공간 경로를 유지하면서 동작 시간의 겹침을 조정합니다.공간 경로 자체가 간격을 만족하지 못하는 사례와 시간 조정으로 해결되는 사례를 구분합니다.기존 경로의 형상을 유지할 필요가 있고 출발 지연으로 해결 가능한 경우
B. 공동 계획 후보 선택
우선 확장		기존 공동 계획에서 거리 검사를 통과할 대체 후보를 제한된 예산 안에서 탐색합니다.전용 선택기의 첫 통과 정책을 기준으로 삼되, 계획·검사·저장 전체에 잔여 예산·취소 확인을 연결해야 합니다.시작·목표는 유효하고 현재 단일 후보가 중간 경로에서 거부되는 경우
C. 거리 제약을 공간 탐색에 반영
비교 후보		탐색 중 유효성 조건과 거리·경로 비용을 연계해 통과 가능한 공간 경로를 찾습니다.모델·거리 정의의 정합, 검사 해상도·호출 비용과 시간 후처리 뒤 재검증을 평가합니다. 거리 비용을 줄이는 것만으로 최소 간격이 보장되지는 않습니다.후보 사후 거부가 반복되어 생성 단계의 제약 반영이 필요한 경우
D. 직선·자세 제약 구간
작업별 확장		접근·후퇴처럼 Cartesian 선형 동작이 필요한 구간을 별도로 정의합니다.Pilz LIN/PTP/CIRC 등은 목표·제한 조건에 맞는 후보입니다. 공구 TCP·기준 프레임·IK·충돌 검사와 자유 공간 이동을 함께 구성해야 합니다.일반 이동과 작업 구간의 경로 요구가 다른 경우
E. 작업 단계 계획
후속 확장		이동·접근·파지·이송·후퇴를 단계별로 구성하고 실패 지점을 관리합니다.MoveIt Task Constructor의 단계 구성을 검토할 수 있습니다. 그리퍼·물체·부착 상태와 Humble 호환성 확인이 먼저 필요합니다.단일 목표를 넘어 물체 상태가 바뀌는 작업 순서가 필요한 경우

A는 현재 기반입니다. B의 일반 서버 통합과 C~E는 제안 단계이며 프로젝트 성능을 새로 비교하지 않았습니다.

유효성 조건

  • 팔 간 간격, 환경 충돌, 관절·속도·가속도 제한을 구분합니다.
  • 사후 평활화·시간 부여·출발 지연이 끝난 최종 spline을 다시 검사합니다.
  • 실행 불가능한 시작·목표와 탐색 실패를 다른 상태로 보고합니다.

후보의 품질 평가

  • 조건을 만족하는 후보 사이에서 관절 이동량·끝단 경로·완료 시간을 비교합니다.
  • 첫 통과 후보는 실행 가능성의 기준선이며 최소 우회 결과가 아닙니다.
  • 가중치·단위·동률 규칙과 계산 비용을 명시하고, 개선이 충돌하면 항목별 결과를 보존합니다.

기술 선택 근거: OMPL의 최적화 목표는 경로 품질을 평가하는 수단입니다. 최소 거리 조건의 유효성 판정과는 역할이 다릅니다. TOTG는 허용 범위 안에서 경로를 바꿀 수 있으므로 프로젝트의 최종 궤적 검사 경계를 유지합니다. [공식 문서]

03 / Development roadmap

계측·경로·작업 단계를 잇는 개발 순서

현재 양팔 요청의 거부·취소·최종 검사를 보존하면서, 빈피킹에 필요한 작업 환경·후보·작업 단계를 추가합니다. 아래 항목은 개발 제안이며 실제 파지·실물 로봇 성능을 확인한 결과가 아닙니다.

P0 · 기준 고정

지연과 홈 복귀 거부의 원인을 고정

  • 같은 요청 ID로 상태/작업 환경 준비 대기 → 계획 서비스 → 출발 탐색·거리 검사 → 최종 검사 → 예약 → 관측 최초 이동·완료를 연결합니다. 기존 계측을 재사용하고 빠진 구간을 보강합니다.
  • 30 mm 조건의 실패 입력·시작/목표·허용오차·모델을 고정합니다. 시작·끝점·중간 위반을 나누고, 출발 조정만으로 해결되지 않는 사례를 보존합니다.
  • 계획 실패·거리 조건 거부·계산 예산 소진·실행 중 정지·취소를 UI와 원본 로그에서 구분합니다. 기준을 완화해 실패를 숨기지 않습니다.

완료 조건

  • 동일 요청의 시간 분해·후보 종류와 실패 단계 확인
  • 시작·끝점·중간 위반 및 무실행 재현 자료 확보
  • 성공·실패·취소 기준 실행과 현재 설정 보존
P1 · 공간 재탐색

일반 요청의 제한된 후보 탐색과 우회 개선

  • 전용 후보 선택기를 일반 서버와 공통화하되 계획·검사·저장 전체에 잔여 예산·취소를 연결합니다. 현재 전용 상한 12개를 일반 요청의 보장값으로 그대로 옮기지 않습니다.
  • 유효한 시작·목표의 중간 거부에는 상대 팔의 위치·움직임을 반영한 공간 후보를 검토합니다. 홈 복귀 경유점도 실제 간격·장애물 검사를 통과해야 합니다.
  • 첫 통과를 실행 가능성 기준선으로 삼고 유효 후보의 관절 이동량·링크 프레임 경로·전체 완료 시간을 비교합니다. 후처리·출발 조정이 끝난 최종 spline을 다시 검사합니다.

완료 조건

  • 후보별 경로·거부 이유·검사 비용과 선택 근거 보존
  • 예산 소진·취소·후보 없음에서 Action 미전송 확인
  • 간격 조건을 유지한 우회 길이·완료 시간 비교
P2 · 작업 모델

빈·그리퍼·TCP와 파지 물체 상태를 구성

  • 기존 공통 바닥·받침대 위에 빈 벽/바닥·고정 장애물·내부 물체를 추가하고 MuJoCo와 MoveIt의 작업 환경 모델을 대조합니다. 점군 ROI·축소·갱신 규칙과 불확실성 여유도 정의합니다.
  • 실제 TCP·기준 프레임·열림/닫힘 그리퍼 형상·물체/하중을 모델링합니다. 파지 전에는 환경 물체, 파지 후에는 부착 물체로 검사할 상태 전환을 설계합니다.
  • 필요한 손가락-목표 물체 접촉만 제한적으로 허용하고 빈·주변 물체의 충돌 검사를 유지합니다. 단순화한 충돌 형상과 검사 간격이 얇은 장애물을 놓치지 않는지 확인합니다.

완료 조건

  • 작업 환경·관절 매핑·TCP·그리퍼 형상 정합 확인

  • 자유 공간 이동 → 접근 → 파지 → 퇴피 → 이송 → 놓기의 각 단계에서 형상·상태·실패 복구를 정의합니다. 파지 뒤 퇴피·이송은 물체를 포함해 다시 검사합니다.
  • 직선 접근 전체의 IK 연속성·관절 점프·특이점·충돌을 확인합니다. 부분 Cartesian 경로를 완성된 동작으로 실행하지 않습니다. 작업 연결은 MTC 또는 명시적 상태기계의 Humble 호환성을 비교합니다.

완료 조건

P4 · 대안 비교

같은 작업·예산에서 비용과 경로 품질을 평가

  • 기준 입력에 교차·큰 이동·좁은 빈·환경 장애물·다양한 시작/목표·유효 경로 없는 조건을 추가합니다. 정상 거부·실패·취소·미실행을 성공률 분모에서 숨기지 않습니다.
  • 현재 RRTConnect·3회 시도를 기준으로 시도 수와 개별 계획 예산을 각각 비교합니다. 0.1/0.2/0.5/1.0 s는 실험 후보이며 달성 시간이나 권장 고정 설정이 아닙니다. 전체 요청 예산과 충돌 검증을 함께 유지합니다.
  • 남은 병목에 따라 Tesseract/TrajOpt의 품질, cuRoboV2의 GPU 비용, OMPL 단독 연결의 계층 비용을 비교합니다. 초기화·워밍업·모델 변환·전송·최종 검사를 포함하고 외부 벤치마크를 전용하지 않습니다.

완료 조건

  • 실행 가능성·최소 간격·경로·계산/완료 시간의 동시 평가
  • 순위 대신 요구 충족·통합 비용에 따른 채택/보류 판단
P5 · 실물·접촉

시뮬레이션과 실물 실행 계약을 검증

  • 공통 궤적 실행 계층 아래에 MuJoCo와 제조사 드라이버/하드웨어 인터페이스를 연결합니다. 드라이버가 ros2_control 플러그인인지 별도 Action 서버인지에 따라 연결점을 정합니다.
  • 관절 순서·rad 단위·좌표계·TCP·한계·시간 기준·상태 나이·추종 오차·동기 시작·취소/중단·완료를 양쪽에서 검증합니다. use_sim_time이나 토픽명 변경만으로 전환 완료로 판단하지 않습니다.
  • 조립의 접촉 구간은 지원되는 힘/순응 제어기로 제어권을 명시적으로 전환합니다. MJPC·Crocoddyl·CasADi는 실제 입력 모드, 내부 서보, 주기·지터·FT 피드백·관측 지연과 모델 오차를 확인한 뒤 별도 실험합니다.

공정한 비교를 위한 실행 조건
  • 동일 PC·ROS/MoveIt·MuJoCo·모델·정책·제어기·시간 스케일을 기록합니다. GUI 유무와 뷰어 동시 실행 여부는 다른 조건으로 관리합니다.
  • 입력 seed 고정과 플래너 내부 난수의 고정 여부를 구분합니다. 같은 목표라도 경로가 매번 같다고 가정하지 않고 워밍업·교대 순서·반복 수를 사전에 정합니다.
  • 코드와 환경이 다른 과거 결과는 참고 자료로 보존합니다. 새 성능 비교는 같은 구현의 명시적 참조/개선 모드 또는 고정된 두 버전을 사용합니다.
  • 작은 표본에는 중앙값·최대값·원본을 제시합니다. 기존 5목표 결과로 p95/p99·전체 작업 공간 성공률을 주장하지 않습니다.
  • native 거리 시간은 후보 평가·탐색 시간의 부분집합입니다. 포함 관계가 있는 구간을 다시 더하지 않습니다. s(wall)와 s(sim)을 분리합니다.
  • 충돌 검사 비율 0.05의 일괄 확대를 지연 개선 수단으로 사용하지 않습니다. 좁은 물체·회전 링크의 검사 누락 여부를 모델·검사 간격과 함께 확인합니다.
