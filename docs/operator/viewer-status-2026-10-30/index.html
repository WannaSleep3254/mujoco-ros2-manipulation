Overview / Current operations

화면은 여섯 개, 실행 역할은 서로 다릅니다

통합 조작, 독립 집기 실험, 기록 재생, ROS 집기 전용 화면이 각각 운영되고 있습니다.

현재 화면을 기능과 운영 목적에 따라 정리한 상태 리포트입니다. 포트 번호는 개발 버전이 아니며, 아래 상태는 조사 시점의 기록입니다. 같은 포트의 서버나 코드가 바뀌면 이 목록도 갱신해야 합니다.

  • 실행 중인 웹 서버 6개의 역할과 조사 시점 상태를 나란히 비교합니다.

Three.js 표시부는 유지하고, 표시 모델·실행 대상·작업 상태를 구분하는 기존 방향을 따릅니다. 여러 서버를 단순히 한 포트로 모으기 전에 작업별 명령과 취소의 소유권을 먼저 정리합니다.

02 / Screens & recordings

각 뷰어의 동작 영상

각 영상은 해당 화면의 표시와 조작 흐름을 보여주는 기능 기록입니다. 8897·8925는 명령을 보내지 않는 계획 미리보기, 8923은 정지 상태의 화면 조작, 8924·8930은 새 물리 시뮬레이션 실행, 8929는 합성 검증 기록의 재생입니다. 브라우저 화면을 간격을 두고 수집해 영상으로 구성했으며 반복 프레임이 포함됩니다. 영상 길이나 인코딩 속도를 뷰어 FPS·로봇 속도의 비교값으로 사용하지 않습니다. 촬영 방법과 구분은 촬영 근거에서 확인합니다.

04 / Proposed integration sequence

향후 통합 순서

현재 검증한 실행 경로를 유지하면서 조작의 진입점과 상태 표시를 먼저 정리합니다. 아래 항목은 후속 계획이며 이 리포트의 게시로 구현 완료되지는 않습니다.

1 · 운영 진입점

기준 화면과 별도 화면의 위치 정리

  • 새 작업실 GUI를 운영 진입점으로 삼을지 검토하고, 통합 조작·ROS 집기·기록 재생의 역할을 표시합니다.
  • 화면 이동 링크를 명시적으로 등록하고, 대상 서버가 없을 때 실행 준비 완료로 표시하지 않습니다.
  • 포트 대신 모델·작업 종류·코드·실행 환경으로 운영 상태를 식별합니다.

완료 조건

  • 운영 기준 주소와 실행 범위를 한곳에서 확인합니다.
  • 링크 이동만으로 작업이 시작되지 않으며, 잘못된 대상 주소를 차단합니다.

작업실 GUI의 현재 반영 · 공통 표시 방향

2 · 작업 흐름

통합 UI에서 작업 선택·상태·취소 연결

  • 관절·TCP 조작과 집기·운반·놓기의 작업 선택, 준비·실행·실패·완료 표시를 설계합니다.
  • 화면을 전환해도 실제 실행 중인 작업과 취소 대상이 바뀌지 않도록 소유권을 연결합니다.
  • 요청 취소, 제어기 정지, 프로세스 정리를 따로 확인하고 자동 재실행·놓기를 추가하지 않습니다.

완료 조건

  • 한 화면에서 현재 작업과 실행·취소 대상을 명확히 확인합니다.
  • 서버·모델·작업 식별자가 바뀌면 이전 명령과 오래된 상태를 재사용하지 않습니다.
  • 정상 완료와 시작 중·운반 중 취소를 같은 UI 경로에서 검증합니다.

W04 작업 책임 분리 · W07 기본 작업

3 · 공통 3D 표시

표시 모델과 실행 모델의 대응 연결

  • 같은 Three.js 화면에서 일반 양팔 모델과 그리퍼·자유 물체가 포함된 집기 모델을 구분합니다.
  • 형상·관절 대응·모델 해시·작업 세대가 현재 실행과 일치할 때만 실제 관측을 표시합니다.
  • 과거 완료 자세, 실시간 관측과 계획 미리보기를 구분합니다.
