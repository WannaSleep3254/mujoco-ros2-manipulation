8933 통합 작업실에 연결한 기능

시작 설정에서 모델·해시·전용 ROS 도메인을 고정합니다. 선택한 작업에서 관절·TCP 조작 또는 집기·운반·놓기를 고르며, 선택만으로 실행하지 않습니다. 집기는 FR5·검증용 평행 그리퍼·단순 블록의 전체 순서입니다.

실행·상태·취소

  • 같은 작업 패널에서 시작하고 접근·집기 확인·운반·놓기·정리를 확인합니다.
  • 물리 집기, MoveIt 부착, Action 종료, 제어기 정지와 소유 프로세스 정리를 구분합니다.
  • 활성 작업이나 정리 미확인이 있으면 전환·새 실행을 막습니다. 취소 뒤 자동 놓기·부착 해제·재실행을 하지 않습니다.
  • 작업 선택 세대가 바뀌면 이전 창의 명령과 늦은 상태·3D 자세를 재사용하지 않습니다.

3D와 기록 분석

  • 일반 양팔 모델과 native 3.12의 그리퍼·자유 블록 모델을 같은 표시부에서 전환합니다.
  • 종료 후 마지막 자세와 실제 수신 중인 관측을 구분합니다.
  • 명시적으로 가져온 센서·3D 보존 기록을 같은 분석 패널에서 재생·탐색합니다.
  • 원래 수집 시각·누락을 유지하고, 기록을 바꾸거나 화면을 떠나면 해당 표시 자원을 정리합니다.

기록의 범위: 대표 입력은 자세 41개·합성 RGB 이미지 18개의 기존 진단 기록입니다. 새 집기 실행의 RGB 센서 수집이나 실제 카메라의 하드웨어 동기화를 확인한 결과는 아닙니다. 기존 0.5초 관측 나이, 150 ms 집기 관측 간격과 물리·접촉·소유 프로세스 정리 기준을 유지합니다.

같은 소스에서 확인한 대표 조건

통합 구현과 아래 실제 ROS 세 조건의 기준은 fd6cebc입니다. 이전 732413f의 통과 기록은 검증 JSON에 별도 이력으로 보존합니다.

통합 소스 fd6cebc에서 실제 HTTP를 통해 다음 세 조건을 순차 실행했습니다. 각 결과의 실행·모델·원본 해시와 소유 프로세스 정리를 확인했습니다.

  • 정상: 집기·운반·놓기 후 물리 해제와 MoveIt world 객체 복귀를 확인했습니다. 일반 조작으로 돌아와 시뮬레이션 시작·계획 생성·검토·폐기·종료를 확인했습니다. 이 회귀에서 그 계획을 승인·실행한 것은 아닙니다.
  • 시작 중 취소: native 실행 전에 취소해 Action 목표 0개와 검사 프로세스 정리를 확인했습니다. native가 시작되지 않았으므로 제어기의 물리 정지를 관측한 결과로 표시하지 않습니다.
  • 운반 중 취소: 실제 물체가 5 mm 이상 움직이고 물리 집기·MoveIt 부착을 확인한 뒤 취소했습니다. 정지 감시와 세 제어기의 비활성, native·작업·검사 프로세스 정리를 확인했습니다. 취소 뒤 현재 물리 집기는 미확인, 계획상 부착은 보존합니다.

단위 검사 전체 1,402개(1개 제외), 모델 검사 전체 91개(1개 제외)와 JavaScript 18개 스크립트의 276개 시나리오를 통과했습니다. 세 실제 검사에는 잘못된 선택 세대·모델·취소 대상 거부와 이전 3D 응답 폐기, 같은 UI의 읽기 전용 재생 검사도 포함합니다.

실패 원본과 수정 범위

첫 시작 중 취소는 Python의 취소 처리 준비 전에 SIGINT가 도착해 종료 코드 -2와 결과 누락으로 실패했습니다. 취소 요청은 즉시 보존하고, 정확한 작업자가 유효한 IPC를 발행한 뒤 신호를 한 번 전달하도록 수정했습니다. 50·57초의 기존 단계적 종료 기준은 유지합니다.

앞선 운반 취소에서는 병렬 검사 중 제조사 저장소의 Git 관리 파일 상태가 바뀌어 파일 식별 검사가 실행을 차단했습니다. 원본을 보존하고 콘솔·작업 프로세스에 읽기 전용 Git 설정을 적용한 뒤 같은 고정 소스에서 순차 검증했습니다. 파일·소스·실행 식별 검사는 유지합니다.

오류 중단과 사용자 취소의 분리

유효한 IPC가 오기 전의 협조적 취소 대기가 오류 중단에도 적용되는 분기를 추가 감사에서 확인했습니다. 잘못된 첫 IPC, 출력·보존 한도, 감시자 오류와 시간 초과는 이 준비 대기를 건너뛰고 정확한 소유 작업자를 즉시 중단하도록 수정했습니다. 사용자 취소·일반 닫기의 준비 대기와 기존 50·57초 단계적 종료는 유지합니다.

준비 중 사용자 취소 뒤 오류가 생기는 경우, 원래 취소 시한 유지, 잘못된 IPC 미수락과 신호 중복 전송 방지를 포함한 단위 검사를 통과했습니다. 결과가 없거나 정리를 확인하지 못한 종료는 성공으로 바꾸지 않습니다. 이 오류 분기 검사는 실제 ROS의 치명적 오류 주입 시험이 아닙니다. 최종 소스에서 정상·사용자 취소 세 조건을 따로 다시 검증했습니다.

검증의 한계: HTTP 응답 시간은 JSON 해석을 포함한 한 호스트의 조회 시간입니다. 화면 FPS·입력부터 제어까지의 지연·취소부터 물리 정지까지의 시간이 아닙니다. 새 UI의 실제 PC·모바일 브라우저 배치와 WebGL 조작·영상 촬영은 브라우저 접근이 비활성화되어 수행하지 않았습니다.
