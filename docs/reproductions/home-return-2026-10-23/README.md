[공통 모듈 경계](../../module_boundaries.md) · [모션 명령](../../motion_requests.md) · [검증 절차](../../../tests/integration/README.md)

이 사례는 공간 재계획 구현 전의 기준 입력입니다. 30 mm 거리 기준과 기존 취소·계산 예산·최종 검사를 유지하며,
실행 전 거부가 시작 자세·목표 자세·중간 경로 중 어디서 발생했는지 확인합니다.

## 재현 명령

모델과 네이티브 런타임이 준비된 저장소에서 실행합니다. 설치·생성 절차는 기존 구조 문서를 따릅니다.

```bash
# ROS 실행 없이 과거 시작·목표·거부 표본의 기하만 재평가
python3 reproduce_motion.py --mode witness

# 새 독립 시뮬레이션에서 고정 시작/홈 목표를 두 전략으로 요청
source ./manipulation_env.sh
python3 reproduce_motion.py --mode live --domain 154

# 새 trace에 저장된 거부 경로를 실행 없이 다시 검사
python3 reproduce_motion.py --mode trace --trace runtime/validation/motion-reproductions/세션/요청_ID.json
```

출력 경로를 지정하려면 `--output`을 사용합니다. 출력은 새 `runtime/` 파일 또는 디렉터리만 허용하며 기존 원본을 덮어쓰지 않습니다.
기하 재평가에는 실행 환경의 Python 의존성과 네이티브 거리 평가기가 필요합니다. `--mode witness`와 `trace`는 ROS 노드를 만들지 않습니다.
CLI `manipulation-reproduce-motion`도 같은 기능입니다. wheel 단독 배포에는 모델·fixture·ROS 런타임이 포함되지 않습니다.

`live`는 사용 중인 도메인을 사전에 거부합니다. 도메인이 사용 중이면 다른 빈 `--domain`을 지정합니다.
원본의 네 단계 준비 목표 중 처음 세 단계는 새로 계획하고, 마지막 단계는 성공 기록에서 추출한 궤적을 재현 전용 어댑터로 공급합니다.
저장 경로의 시작점과 현재 상태 차이가 0.01 rad 이내인지 확인하고 시작점을 현재 정지 상태로 맞춘 뒤,
변경된 전체 spline을 거리·MoveIt·예산·상태 재확인 검사를 통과시킵니다. 이후 기록된 실제 시작 자세로 미세 정렬합니다.
저장 경로의 원래 목표 허용오차는 0.003 rad이며, 새 계획의 0.00001 rad 설정으로 생성됐다고 표시하지 않습니다.
저장 경로에는 계획 서비스 왕복·MoveIt planning_time이 없으므로 null로 기록하고 준비 시간으로만 취급합니다.
이는 과거 전체 명령·시각을 그대로 재생하는 절차가 아니라 고정 상태를 만드는 새 준비 실행입니다.
어느 준비 경로든 검사를 통과하지 못하면 실행을 중단하고 실패 원본을 남깁니다.
정렬 후 시작 오차는 최대 0.0015 rad로 확인하며, 준비 요청과 홈 복귀 요청은 따로 기록합니다.

`--repeats 1..5`는 전략별 새 요청 수입니다. 매 요청의 실제 시작·목표·계산 예산·관절 허용오차와
관측 결과를 남깁니다. MoveIt 경로는 비결정적이므로 같은 입력에서 새 경로가 통과할 수도 있습니다.
이를 숨기거나 실패가 나올 때까지 무제한 재시도하지 않습니다. 이 작은 재현은 성공률·p95 성능평가가 아닙니다.

## 자산 정체성과 저장 내용

fixture는 공개 추출본 자체의 SHA와 요청 ID·명령·실제 시작 상태·거부 표본을 대조합니다.
작업장면 fingerprint, 설정 SHA, 저장소 경로를 정규화한 XML SHA와 mesh 34개의 내용을 고정합니다.
과거 raw XML SHA와 일치하는 로컬 생성물을 기준으로 정규화 해시를 만들었습니다.
새 빌드의 절대경로와 native binary SHA는 달라질 수 있으므로 비교값을 기록하고,
기하·네이티브 소스·MuJoCo 버전이 바뀌면 같은 fixture의 재현으로 취급하지 않습니다.

새 세션의 `session.json`에는 `workcell_contract`가 들어갑니다. 새 요청 trace는 다음을 보존합니다.

- 완전한 시작/목표와 원천 상태 stamp·수신 age, 시작/목표의 거리 진단입니다.
- ROS 메시지와 분리된 Spline 표현의 `source_trajectories`와 `planned_trajectories`입니다. 실패한 경로도 보존합니다.
- `failure_stage`, 전송 수, Action 결과, 관측 최초 이동·정착·취소·최종 결과입니다.
- 정지 상태 snapshot, endpoint 측정, 계획 서비스, 출발 탐색, 최종 검사, 계획 후 상태 재확인 구간입니다.

`reproduction.json`은 준비/홈 요청·trace SHA·시작 오차·같은 실패 발생 여부·시간 분해를 연결합니다.
전체 검증기의 `result.json`과 native `physics.json`에서 접촉·시계·종료 결과를 함께 확인합니다.

`trace` 모드는 같은 생성물·정책의 저장된 궤적에 한정합니다. 공동 계획은 최종 spline을 다시 검사하고,
출발 조정은 저장한 팔별 원래 spline으로 동일한 제한 탐색을 다시 수행합니다.
이 결과는 MuJoCo 기하 재평가이며 MoveIt 장면 유효성, 실제 추종, 연속시간 안전성의 대체 검사가 아닙니다.
기존 과거 trace에 `planned_trajectories`가 없으면 전체 경로 재검사 대신 witness 모드를 사용해야 합니다.

## 시간과 실패 해석

wall 구간에는 단일 기록 프로세스의 `time.monotonic_ns`를 사용하고 시뮬레이션 시각과 더하지 않습니다.
계산 예산은 정지 상태 snapshot 이후부터 적용하며, 계산 완료 후 1 simulation초의 실행 예약은 별도입니다.
계획 서비스 왕복에서 MoveIt `planning_time`을 뺀 차이는 순수 DDS 지연이 아닙니다.
실행이 없으면 최초 이동은 null입니다. 최종 이벤트가 terminal이어도 `failure_stage`로 실제 실패 단계를 확인합니다.

거리 미달은 현재 서버에서 `failed`와 `dispatched_goals=0`인 실행 전 실패입니다.
잘못된 명령의 입장 `rejected`, 궤적 전송 이후의 실행 실패, 취소 완료와 구분합니다.
계획 30 mm·관측 20 mm·네이티브 접촉/시계 정지 조건은 이번 변경에서 유지합니다.

## 공개 자료의 범위

이 디렉터리의 JSON/gzip은 완전한 원본이 아니라 **필요한 측정 필드만 허용한 공개용 추출본**입니다.
완전한 과거·현재 원본 13개와 추출 전 fixture는 로컬에 그대로 보존했습니다.
호스트·실행 환경 메타데이터, 개인 절대경로, 프로세스 ID, 단조 시계의 절대 원점과 관측 자세 전체는 공개 추출본에서 제외했습니다.
유지한 관절 목표·시작·궤적·거리·상대 시간 값은 원본과 동일하며 재계산하거나 반올림하지 않았습니다.

각 파일의 `evidence_export.raw_source_sha256`은 로컬의 완전한 원본을 식별합니다.
fixture와 검증 요약의 파일 SHA는 실제로 읽는 공개 추출본을 식별하므로 두 종류의 해시를 구분합니다.
준비 궤적의 압축 파일 SHA와 `source_trace_sha256`은 각각 공개 추출본의 gzip 바이트와 압축 해제 JSON 바이트에 적용합니다.
공개 자료만으로 비공개 원본의 생략된 필드를 복원하거나 직접 대조할 수 있다는 뜻은 아닙니다.
[공개 후보 검사 기록](evidence/privacy-audit.json)은 실제 추출본에 적용한 필터와 SHA 대조 범위를 보여줍니다.

[추출 도구](../../../scripts/export_motion_evidence.py)는 현재 검증된 모션 기록 형식만 대상으로 합니다.
허용한 필드만 복사하고, 개인 경로·특정 환경 필드·이메일·자격정보 형태의 문자열을 거부합니다.
모든 임의 문서의 개인정보를 자동으로 탐지한다는 보장은 없으며, 새 형식과 자유 문구는 공개 전에 별도 검토해야 합니다.
